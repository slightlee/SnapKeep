# 发布流程（最小版）

目标：确保版本号、文档与发布记录一致，避免散落硬编码。

## 1. 确认版本号
- 按 `doc/版本定义规范.md` 选择目标版本。
- 若为预发布，使用 `alpha` / `beta` / `rc` 标识。

## 2. 更新版本常量
- 修改 `frontend/src/constants/version.js` 中版本与阶段标识。
- 同步 `frontend/package.json` 的 `version` 字段（不带 `v`）。

## 3. 同步文档与设计稿
- 更新 PRD 与技术方案文档版本号与文件名。
- 更新 `CHANGELOG.md`，记录本次变更摘要。
- 如有 UI 设计稿，更新文件名与版本文案。

## 4. 验证
- 运行基础测试或手动回归（视阶段而定）。前端项目位于 `frontend/`。
- 打开页面确认版本号显示正确、导出/备份 `version` 字段一致。

## 5. 发布
- 生成发布说明（可从 `CHANGELOG.md` 摘要）。
- 创建附注标签（annotated tag），Tag 名与版本号保持一致并带 `v` 前缀。
- Tag 说明文字统一使用：`release: vX.Y.Z[-PRERELEASE]`。
- Tag 优先打在版本提交上；若该版本没有单独的版本提交，则必须确认目标提交上的版本号、文档和 `CHANGELOG` 已与该版本一致。

示例：
- `git tag -a "v0.1.0-alpha.1" "<commit-id>" -m "release: v0.1.0-alpha.1"`
- `git push origin "v0.1.0-alpha.1"`
