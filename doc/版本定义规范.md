# 版本定义规范

## 1. 版本格式
版本号遵循 SemVer：
- `vMAJOR.MINOR.PATCH[-PRERELEASE][+BUILD]`

说明：
- `MAJOR`：不兼容变更。
- `MINOR`：向后兼容的新功能。
- `PATCH`：向后兼容的修复。
- `PRERELEASE`：预发布标识（`alpha`、`beta`、`rc`）。
- `BUILD`：构建元信息（可选，不参与版本比较）。

## 2. 阶段与标识
- `alpha`：内测阶段，可用但不承诺稳定。
- `beta`：公测阶段，功能趋稳，允许小范围不兼容修复。
- `rc`：正式候选，仅允许修复。

示例：
- 内测：`v0.1.0-alpha.1`
- 公测：`v0.9.0-beta.1`
- 候选：`v1.0.0-rc.1`
- 正式：`v1.0.0`

## 3. 版本递增规则
- 破坏性变更：递增 `MAJOR`。
- 新功能：递增 `MINOR`。
- 修复：递增 `PATCH`。
- 预发布序号：递增 `PRERELEASE` 序号（如 `alpha.2`）。

## 4. 使用位置规范
- 文档标题与文档版本：使用带 `v` 的版本号。
- UI 展示：使用带 `v` 的版本号。
- 数据文件字段（如导出/备份 `version`）：使用不带 `v` 的版本号。
- `package.json`：使用不带 `v` 的版本号。
- 版本常量：集中定义在 `frontend/src/constants/version.js`，避免散落硬编码。

## 5. 文件命名规范
- PRD：`doc/SnapKeep产品需求文档（PRD）- vX.Y.Z-<tag>.md`
- 技术方案：`doc/SnapKeep技术方案设计文档-vX.Y.Z-<tag>.md`
- UI 设计稿：`design/ui-design-vX.Y.Z-<tag>.html`

## 6. 发布流程最小清单
- 更新 `package.json` 版本号。
- 更新文档版本号与文件名。
- 更新 UI 展示版本号与数据版本字段。
- 更新 `CHANGELOG.md`。
